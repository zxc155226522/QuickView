## CDR 导出"糊"的根因诊断（08-15 09:30）
- K33 / OLEADER：libcdr 输出为真矢量（SVG 只有 `<path>`/`<text>`，0 个 `<image>`），12000px 导出（8485×11997）线条锐利，**并非渲染器问题**。
- PODBX260729-K34：SVG 含 84 path + 1 个 `<image>` 嵌入位图，照片区域放大必然糊，属源文件天花板。
- 结论："糊"要么来自源文件嵌入位图，要么是 PNG 被查看器放大超过原始像素；单纯提高 PNG 分辨率无法让位图源变清晰。
- 最接近 Inkscape 的做法：保留矢量，导出为 SVG（而非 PNG），可在 Inkscape/浏览器里无限放大。如用户需要，可加 `--export-svg` 命令行。

## 新增 --export-svg（原生纯净 SVG 导出）
- 需求：用户要"看 CDR 矢量内容"，不要被白底/边框/裁白边处理（之前 --export-png 是位图，糊）。
- 实现：ImageLoader.cpp `ExportToSvg(inPath,outPath)` 对 CDR/CMX 直接走 libcdr 原始解析（`RVNGStringStream`+`RVNGSVGDrawingGenerator`），取 `svgPages[0]` 原生串，**跳过** LoadCDR 的"白底画布 rect / 裁白边 / 样式内联"，写 UTF-8 无 BOM。SVG/PLT/DXF/DWG 复用 LoadToFrame 成品（这些已是干净原生 SVG）。main.cpp 加 `ToolMode::ExportSvg` + `RunExportSvg` + 分派。
- 提交：改动前 `b7189ea`，改动后 `469f47e`。桌面 3 个 CDR 已导出：`K33.svg`/`OLEADER.svg`（纯矢量，0 白底 0 嵌入图）`PODBX260729-K34.svg`（45MB，含 1 张嵌入位图，矢量部分无限锐利）。

## 根因：resvg 丢内嵌 BMP 位图（08-15 11:30）
- PODBX260729-K34.svg 内嵌位图是 `data:image/bmp;base64,...`（Corel 导出 32 位 BMP，文件头 424D）。
- resvg/usvg 只认 `image/png|jpeg|gif|webp` 四种 MIME（`usvg/src/parser/image.rs` 的 `image_href_resolver`），`image/bmp` 返回 None → `<image>` 被静默丢弃。D2D 缩略图本就不渲染 `<image>`。两条路径都丢位图，浏览器（原生支持 BMP）正常 → 现象完全吻合。
- 对照：8×8 红 PNG 内嵌能被 resvg 正常渲染，证明 raster-images 特性开着，问题仅针对 BMP。
- 修复方向（未实施，等用户定方向）：
  1. 最小改动：SVG 后处理识别 `data:image/bmp`，用 Windows WIC（零依赖、原生解 BMP）解码后转 PNG 内联回 SVG，再交 resvg。缩略图 D2D 路径是否要位图另议。
  2. 换 Skia：SkCodec 原生解 BMP + SVG(SkSVGDOM) + D3D11/Vulkan GPU 后端，开箱解决 BMP+大文件+GPU，但渲染管线大改（主视图+缩略图+导出全换）。
  3. thorvg 不可取：其解码列表 JPG/PNG/WebP/raw，同样不含 BMP，换它根因不变。
- 另："糊"与 GPU 无关，疑似主视图 resvg 渲染未按 DPR/HiDPI 出图被放大插值（浏览器用了 devicePixelRatio）；属独立 render-scale bug，待查。
