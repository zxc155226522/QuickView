# 2026-08-11 缩略图 ShellEx 收尾与 UserChoice 覆盖层根因

## 事实（注册表实测）
- `HKCU\.svg` 默认 = `QuickView.Vector`；`QuickView.Vector\ShellEx\{E357FCCD...}` = 我们的 CLSID；`.svg\ShellEx`(扩展名级) = 我们的 CLSID —— **我们注册没问题**。
- `FileExts\.svg\UserChoice` = `WPS.PIC.svg`（哈希 `V3GpbncZ/mg=` 未变），受保护。
- `WPS.PIC.svg\ShellEx` 在用户「关 WPS 关联」时被 WPS 重置抹掉（之前注入的被擦）。
- 对照 `.ai\UserChoice` = (not found) → 无覆盖层 → 正常出图。

## 根因
Windows 缩略图归属优先级：`UserChoice`(受保护) > ProgID 级 ShellEx > 扩展名级 ShellEx。
`.svg` 的 UserChoice 锁死 WPS，覆盖了我们所有注册。AI/PDF 能出是因链路最终落到 QuickView.Vector。
用户直觉「你们没注册到」只对一半：注册了，但没抢 UserChoice 这层（RegisterAssociations 不碰 UserChoice）。

## 已验证的死路
- 删 `UserChoice` 键：PowerShell `Remove-Item` 报 "Cannot delete a subkey tree because the subkey does not exist" —— 哈希保护，标准 API 删不掉。
- 清 `thumbcache_*.db`：系统持锁 + explorer 被杀瞬时自启重新加锁，删不掉（但无害，无负向缓存概念）。

## 临时修复（已实施）
向 `WPS.PIC.svg\ShellEx\{E357FCCD...}` 注入我们的 CLSID（WPS.PIC.svg 现为 handler-less 空 ProgID，UserChoice 仍指向它）→ Explorer 经 UserChoice 走到该 ProgID 即命中我们 provider。待用户目视验证。

## 永久修复方向（待用户批准）
1. 路A（用户）：Windows 设置→默认应用→.svg→QuickView，合法重写 UserChoice，且 WPS 已关关联不会抢回。

## 增补：为什么「手动设置能、裸写注册表不能」（用户 02:14 提问）
UserChoice 子键除 ProgID 外还有 `Hash` 防伪印。机制：
- 手动设置（设置 UI）走**官方默认应用 API**，由系统用当前用户令牌生成合法 Hash + 广播 `SHChangeNotify` 让 Explorer 重载 + 触发缩略图缓存刷新 → 系统认可。
- 第三方脚本/程序**裸写注册表值**改 ProgID 或在被抢 ProgID 下挂 ShellEx：① 写不出合法 Hash（算法系统私有+绑定登录令牌），系统判定 UserChoice 损坏/无效→忽略或保持原值；② 触发不了系统级缓存刷新。
- 故「路B 注入 UserChoice 指向的 ProgID」也绕不过 Hash：只要 UserChoice 仍合法指向别人，往那条链挂 ShellEx 属寄生且不优雅，WPS 还可能注册自己的预览处理器挡在前面。
- **正确代码方向**：让程序调用官方 `IApplicationAssociationRegistration`/`SetAppAsDefault` 设自身为默认（同手动的官方通道，合法带 Hash）；或设置界面加按钮直接弹系统"默认应用"面板让用户点。换电脑运行一次即自动合法接管，portable。

## 新根因：桌面 SVG 带 UTF-8 BOM → magic 检测失败（02:25 用户报"有的SVG能显、桌面几个不行"）
- 实测桌面 3 个 SVG 前 8 字节均为 `EF BB BF 3C 73 76 67 20` = UTF-8 BOM + `<svg `。
- `ThumbnailProvider.cpp` magic 检测（约 L353-355）只在缓冲区**第 0 字节**比 `<?xml`/`<?svg`/`svg`，带 BOM 时第 0 字节是 0xEF 不匹配 → 落到 L357-364 的 ASCII 兜底：BOM 字节无 NUL → `asc=true` → 误判 `ext=plt`(HPGL) → worker 按绘图文件渲染 SVG 失败 → 不出图。
- 能正常显示的 SVG 是无 BOM、第 0 字节即 `<svg` 的文件。App 本体打开不受影响（走真实扩展名+自有解析器），仅 Explorer 缩略图出此问题。
- 修复方向：magic 检测前跳过 UTF-8 BOM（EF BB BF），用跳过后的指针/长度做后续所有格式匹配。仅改 `ThumbnailProvider.cpp` 一处。

## 缩略图通道拆分修复（11:2x–12:1x：周氏目录"CDR/大文件缩略图加载不了"）
- 根因三关：①CDR+大文件混用串行通道 `kSerialCap=4` 队列满→stale 丢弃；②provider `kMaxBytes=200MB` 超限 abort；③客户端管道 `kWorkerTimeoutMs=15000` 超时砍慢渲染。
- 用户批准方案(含 Stale 兜底 C)：CDR/大文件各独立单线程 + 小文件并行默认4线程 + 管道超时15s→60s + 大文件降级渲染(size 钳128) + CDR 加速(独立线程隔离) + Stale 兜底一次性 worker。
