## 关键根因修正（commit 0b233b4）—— 真实路径为何取不到
- 之前的 SetSite/IShellItem 思路是错的：Explorer 对缩略图提供器**优先用 IInitializeWithStream**（只给字节流），**从不调用 SetSite**，也**不调用 IInitializeWithFile**。所以 SetSite 拿不到路径、`m_realPath` 永远空，magic 又识别不了大量文件 → `ext=bin` 2503 次、角标全无。
- **正确解法**：在 QI 里**不暴露 IInitializeWithStream**，Shell 会回退到 `IInitializeWithFile::Initialize(pszFilePath)` 直接拿到真实文件路径。`m_path` 即真实文件，角标扩展名与 worker 解码均用真实文件名，无需 magic。日志印证：删流接口后 QI 显示 `IInitializeWithStream->NOINTERFACE`、`IInitFile OK`。
- 删除：IInitializeWithStream::Initialize 方法体 + 类声明里的 IInitializeWithStream 基类；SetSite 置空实现。
- 注意：去掉 IInitializeWithStream 后，仅能以流方式存在的项目（压缩包内文件、部分搜索结果）将无法生成缩略图（本地普通文件不受影响）。

## ⚠️ 重要纠正（同日晚，commit 77d6615）—— 0b233b4 思路在本机是错的、且造成全无缩略图
- **实测结论（铁证）**：本机 Explorer 初始化缩略图提供程序时，QI 探测顺序只有 `IThumbnailProvider` 与 `IInitializeWithStream`；当 `IInitializeWithStream->NOINTERFACE` 后，**不会回退到 `IInitializeWithFile`**，于是 `GetThumbnail` 永远不被调用 → 缩略图全无。删除 IInitializeWithStream（0b233b4）是直接回归。
- **正确做法**：提供程序**必须实现 `IInitializeWithStream`**（Explorer 才会调用 GetThumbnail，提取才恢复）。真实文件名扩展名通过 `IInitializeWithStream::Initialize` 里的 **`IStream::Stat(&stg, STATFLAG_DEFAULT)` 取 `stg.pwcsName`** 获得（Explorer 提供的文件流，Stat 名称通常是真实全路径，实测对 .cdr/.ai/.plt/.pdf/.svg/.dwg/.dxf/.tif 均返回正确扩展名）。多重保险再叠加 `IObjectWithSite::SetSite`→`IShellItem::GetDisplayName` 与 `IInitializeWithFile`。
- worker 解码输入仍用"流落盘临时文件"（magic 命名），保证提取稳定；角标扩展名优先用 Stat/Site/InitFile 的真实路径，取不到才退回临时文件名 magic 扩展名。
- 验证：程序化触发提取，`GetThumbnail=111 / OK=111 / worker_failed=0`，`realPath(Stat)` 全为真实文件名 → 角标正确，BIN 消失。
- **经验法则（可复用）**：Windows 资源管理器缩略图提供程序，在这类环境里 IInitializeWithStream 是"必需"而非"可选"；想拿真实路径用 IStream::Stat 名称，别指望 IInitializeWithFile 回退或 SetSite。注册用 HKCU\Software\Classes（无需管理员），regsvr32 被安全策略当 LOLBin 拦截时，可用 PowerShell 直接写等价注册表项（CLSID/InprocServer32 + 各扩展名 ShellEx\{E357FCCD-A995-4576-B01F-234630154E96}）。

## ⚠️ GDI+ 圆角矩形半径语义坑（commit 3167d95）—— 胶囊左下角"缺块"
- **现象**：角标两端本应半圆胶囊，却呈现方角+极小圆角，左下角视觉像缺一块。
- **根因**：`AddRoundedRect(path, x,y,w,h, r)` 里 `AddArc(x,y, r,r, ...)` 的 rect 边长 = r，所以**实际圆角半径 = r/2**；调用处传 `r = bh*0.5`，且 clamp `r <= min(w,h)*0.5`，导致最大圆角半径仅 `bh/4`，永远画不出半圆。
- **修复**：参数语义改为"直接表示圆角半径"，弧外接矩形边长 = `2*radius`（`const float d = radius*2; AddArc(x,y,d,d,...)`），clamp 改为 `radius <= min(w,h)/2`；调用传 `radius = bh*0.5` 即得真半圆胶囊。
- 同时 `margin` 由 `max(4, h*0.04)` 调至 `max(6, h*0.06)`，角标与图内图标间隔更大，避免重叠。
- **验证技巧**：用 Python+PIL 严格复现 GraphicsPath 的 line+arc 几何（arc 采样点成多边形），把角标轮廓渲染成 PNG 放大对比，可在改 C++ 前就肉眼确认缺块，不必反复编译 Explorer 侧 DLL。
- 注意：缩略图缓存 key 基于原图内容而非角标，改角标后必须清 `thumbcache_*.db` 才会在已浏览文件夹生效。

## 胶囊绘制最终形态（commit ebb43af）—— 修 BL 真缺块 + 实色 + 缓存
- **真因（铁证，3167d95 仍坏）**：`AddRoundedRect` 左下角(BL)弧的外接矩形 x 坐标误写 `x + radius`（应为 `x`）。标准四角：TL/BL 用 `x`，TR/BR 用 `x+w-d`。错写导致 BL 弧右移 `radius(≈bh/2)`、左下角真缺一块。此前用 PIL **多边形填充**复现（填充补全了错位区）掩盖了 bug；真实 GDI+ `FillPath` 按轮廓走才暴露（用户肉眼看到"还是不行"）。
- **验证技巧修正**：用 `ImageDraw.rounded_rectangle(radius=bh/2)` 渲染轮廓/stroke 看 BL 形状，比多边形填充更准；或直接看真实 GDI+ 输出。对比图：`_diag_BL_current.png`(坏) / `_diag_BL_fixed.png`(好)。
- **胶囊实色**：填充 alpha 170→255（实色），胶囊位图其余区域 alpha=0（透明）。`DrawImage` alpha 混合时仅胶囊区覆盖图、背景透明不覆盖（用户明确要求：胶囊不透明，只有背景透明）。
- **胶囊缓存**：`CreateBadgeBmp(ext, fontSize, outW, outH)` 预渲染独立 `Gdiplus::Bitmap`（临时位图量字宽→Clear透明→FillPath实色胶囊+白字）；`s_badgeMtx`+`s_badgeCache`(`map<wstring,unique_ptr<Bitmap>>`, key=`ext@字号档`)，`CompositeTypeBadge` 查缓存未命中才生成，之后 `g.DrawImage(badge,x,y,bw,bh)` 一次 blit 复用，省每次 `MeasureString/FillPath/DrawString`（文字光栅化最贵）。double-check 防并发重复生成。
- 验证：Release-LTO 编译通过(5s)；提取 GetThumbnail=111/OK=111/worker_failed=0。
